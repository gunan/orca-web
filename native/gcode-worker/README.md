# Native G-code preview worker

This read-only helper compiles OrcaSlicer 2.4.2 at commit `8500fcdccaa10b5099ac20d252af3a7c560046f1`. It runs the same `GCodeProcessor::process_file` used for imported G-code and the original libvgcode conversion, timing statistics, color ranges and segment geometry extraction. It does not execute G-code, connect to a printer, rewrite input, or estimate time with a JavaScript motion model.

Build explicitly with `npm run build:native:gcode` (or `python3 native/gcode-worker/scripts/build.py`). The recipe is validated on macOS with the Command Line Tools and Ninja. It shares the pinned source and dependency cache used by `native/emboss-worker`; on a fresh cache its existing verified bootstrap also builds the emboss helper. This is never triggered by an HTTP request or server startup.

The default result is `.native-cache/gcode-build/orca-gcode-worker`. `ORCA_NATIVE_CACHE_DIR` changes the common cache; `ORCA_GCODE_BUILD_DIR` changes only this build/output directory. `ORCA_SOURCE_DIR`, `ORCA_NATIVE_PREFIX` and `ORCA_NATIVE_DEPENDENCIES` can point to an already populated pinned cache. `CMAKE` and `ORCA_NATIVE_BUILD_JOBS` are explicit build overrides (maximum four concurrent compilation jobs). Source extraction verifies the pinned commit, clean tracked source and the checked-in source hashes. Build manifests record the binary hash, compiler, architecture and dependency provenance.

The server uses `ORCA_GCODE_WORKER_BIN`, then the default cache path. `ORCA_RESOURCES_DIR` points to installed Orca resources when needed. A missing worker leaves the existing source-only preview usable and marks native timing unavailable. Native acceptance tests require the helper and fail rather than skip if it is missing.

The CLI protocol is `orca-gcode-worker input.gcode output.json [resources-directory]`, or `--version`. Output schema 1 contains compact native vertices, actual source-line IDs, layers, normal/available stealth statistics, per-role material use, colors and linear/logarithmic ranges. Inputs are limited to 25 MB, 250,000 processed moves and 500,000 render vertices; output is limited to 128 MiB, CPU to 60 seconds on supported Unix hosts, and the JS worker adds a whole-operation deadline including queue wait, cancellation and bounded queue limits. It reads a private snapshot of an owned ready job. The wrapper creates and removes private temporary files for every invocation.

Native changes are intentionally narrow: the unreachable `run_post_process` rewrite branch throws (the read-only entry point calls `finalize(false)`); unrelated print/thumbnail helpers are extracted verbatim to avoid linking the GUI; pressure-advance command availability is recorded alongside the original native assignments. The original processor leaves its pressure-advance member uninitialized before the first setter. Static object storage prevents undefined values in this helper, and exported pressure advance remains `null` until a native-recognized command. This is not a claim that zero pressure advance was present in the file.

OrcaSlicer source and derivatives use AGPL-3.0; `LICENSE.txt` is retained here. Common dependency archives and hashes are listed in `dependency-manifest.json`; the shared bootstrap retains their respective licenses in the cache. No generated C++ extraction, full upstream checkout, dependency archive or executable needs to be committed. The build recipe plus pinned source provide the corresponding source for the helper.
