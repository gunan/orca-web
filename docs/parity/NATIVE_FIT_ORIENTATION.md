# Orientation-preserving Fit

Pinned native Camera::zoom_to_box and zoom_to_volumes update zoom and target without selecting another view or changing the rotation matrix. Before this change, web Prepare Fit and Zoom to bed selected Isometric, and Preview Fit toolpaths also reset to a fixed direction. The original source hashes and scope are retained in [source evidence](M40_CAMERA_SOURCE.json).

Manual Fit now uses the settled current camera axes in both Prepare projections and Preview. Prepare's delayed tower replacement retains those axes when completing a pending Fit; a later user gesture still cancels that pending fit. Explicit named views and the existing automatic plate-framing policy keep their previous behavior. Preview uses the same eight-corner frustum fit with its own Y-up world conversion instead of a largest-dimension estimate. It uses the selected layer/feature path bounds and changes no slice or geometry data.

Four focused unit checks pass, covering named views, arbitrary and rolled axes, exact pole directions, translations, all eight bounds corners across portrait/square/landscape views, both projection extents and invalid-axis rejection. [Unit log](M40_FIT_UNIT.log).

All three new browser cases fail against the previous build on actual camera-matrix orientation. The initial fix passed those cases but also preserved Front during an automatic plate switch, changing the existing plate policy. Initial automatic fits now request Isometric explicitly; manual and pending fits preserve the user's direction. All18 focused browser cases pass, including the existing delayed-tower lifecycle cases and two new custom-view pending-Fit cases. Geometry/save/Undo isolation and Zoom to bed are covered. [Baseline](M40_FIT_BEFORE.log), [initial run](M40_FIT_BROWSER_INITIAL.log), [final run](M40_FIT_BROWSER.log), [traces](M40_FIT_DIAGNOSTICS.zip).

The installed-native browser test imports the retained native GUI cube and slices it with OrcaSlicer2.4.2. It checks viewing-axis preservation in Prepare and Preview, independently projects every selected native path endpoint through the actual rendered camera matrices, then repeats for a restricted layer range. All selected endpoints fit with the intended margin and only one slice is submitted. [Native test](M40_FIT_NATIVE_BROWSER.log), [observed browser output](M40_NATIVE_FIT_PRESERVED_VIEW.png).

This fixes orientation preservation, not the entire native camera implementation. Native zoom/projection construction, margin1.025 versus the web's1.1, selection framing, scene-versus-volume framing, exact named-view behavior, automatic plate framing, the native view cube and paired desktop pixel acceptance remain open. The web uses its current field of view and frustum-safe fitting calculation. Camera parity remains partial.
