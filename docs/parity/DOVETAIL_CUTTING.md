# Dovetail cutting against native 2.4.2

The web Cut dialog now has a functional Dovetail mode. It generates closed mating tongue/socket geometry from the selected native object group, including depth, width, both clearances, flap angle, groove taper, repeated count/gap and in-plane direction. It retains one or both sides and uses existing group placement and cut-family lifecycle. This is source-backed geometry support, not complete native cut UI parity.

## Source and representation

The baseline is revision `8500fcdccaa10b5099ac20d252af3a7c560046f1`. [CutUtils::perform_with_groove](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/CutUtils.cpp#L557) first separates an upper/lower depth slab, isolates each repeated groove, assigns both angled outside flaps to the lower object, and trims the upper tongue with depth/width clearances. [calculate_groove_width](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/CutUtils.cpp#L768) includes the native object-radius taper allowance when spacing grooves. The web port preserves these ordered half-space intersections and float parameter calculations, then uses the separately verified closed planar clipper. It does not substitute boxes or zero-area faces for the mating surfaces.

Native later concatenates solid fragments into one mesh, retaining internal closed interfaces. The web retains individually manifold fragments as normal volumes in the same cut object; native slicing combines their solids. This preserves editable grouping while avoiding a claim of identical native triangulation. The three native differential fixtures prove identical resulting motion commands for their tested shapes.

[GLGizmoCut](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Gizmos/GLGizmoCut.cpp#L2887) supplies flap angles 30–120°, groove taper 0–15°, count 1–100, default gap 10 mm and default clearances 0.1 mm. Clearance bounds are −0.1 through min(30% of the dimension, 1.5 mm). The native preview's four groove-boundary probes must intersect solid geometry; missing or collapsed tongues fail. Arbitrary plane normals and an in-plane direction are supported.

Native's active [fixed grabber](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Gizmos/GLGizmoBase.hpp#L17) initializes depth from inverse viewport zoom (`max(1,16×inverseZoom)`) and width to four times depth. `dovetailDefaults` supports that input, but the current browser dialog uses the source's geometry-size fallback because native viewport zoom is not available. Numeric defaults therefore are not certified as identical to the native current view.

## Metadata and explicit limits

Both retained sides receive the same native cut identity; the family checksum increments once, existing connector count remains unchanged and peers update through the existing `cutFamilyUpdate` transaction. Existing processed connector metadata/names are retained when unambiguous. A connector split into multiple fragments on one side is rejected instead of duplicating its identity. Existing modifiers/negative volumes are copied intact to intersecting cut-side bounds, following native distribution semantics. Hidden normal parts are retained. Variable layer profiles whose height becomes invalid are cleared. Topology changes require the existing explicit painting-loss consent; source construction/brim attachment metadata is not misapplied to new faces.

Normal parts currently require one filament and no per-part setting overrides; object settings remain supported. Planar connector placement is unavailable in dovetail mode. The web subset requires nonnegative gaps, positive dimensions, at most 200,000 source triangles, eight million contour-check triangle operations, twenty million clipping triangle operations, and the existing two-million output triangle limit. Ambiguous/non-manifold cuts fail without changing the source. Automatic exact native face orientation, viewport-matched initial sizing, arbitrary per-part settings/multimaterial merging and GUI/physical fit validation remain incomplete.

## Executed evidence

- **11 unit checks**: six independent compiled C++ plane fixtures, analytic clearance volume, closed single/repeated/tapered/oblique geometry, retain/placement, family/connector/modifier preservation, invalid inputs, hidden-part retention and complete native project roundtrip. [Reference provenance](../../tests/fixtures/dovetail/README.md) documents float math and the distinction between source and engine evidence.
- **3 real native 2.4.2 checks**: basic, repeated and tapered complete projects match independently generated source-plane projects for **17,139 / 17,809 / 17,139 motion commands**. Native preview extrusion proves first-layer tongue deposition and raised socket flaps; **71 / 97 / 70** socket-layer moves are sampled to ensure they avoid central mating cavities. Every generated fragment is closed and cut-family metadata survives native-project re-import.
- **3 browser checks**: actual Cut dialog generation, all key geometry controls, invalid fit/range rejection, preserved metadata, mode switching, and mandatory painting-loss consent. The harness uses real geometry functions; it does not fabricate generated meshes.

All listed checks pass without skips. A first probe exposed native float trigonometric overloads; the port now retains the intermediate float arithmetic and documents the remaining platform-level `tanf` ULP difference. A native test initially asserted socket height above the entire groove top; correcting the assertion to the source's lower-body/top interval proved the intended geometry. No printer was contacted, no physical fit was measured, and no native GUI byte-equality claim is made.
