# Native printer hotend assets

Source: OrcaSlicer 2.4.2, commit `8500fcdccaa10b5099ac20d252af3a7c560046f1`. This extends the active sequential tool marker; it does not enable the release-disabled libvgcode CoG/tool-marker features.

The native system preset lookup uses its owning vendor and the vendor index's model ID. The custom-printer lookup uses the model display name: the first match within a vendor, but the last matching vendor in lexical order. Those identities are different even though installed model IDs and display names currently coincide. Empty custom names use the original `MyKlipper 0.4 nozzle` alias. Native resource priority is configured user vendor asset, bundled vendor asset, then `profiles/hotend.stl`. A declared but missing vendor asset therefore uses the native default.

The catalog now preserves vendor-index IDs, resolved display names, resource names and provenance. All three job-creation paths freeze this identity in `job.nativeHotend` before enqueueing. Later preset edits/deletion cannot retarget a completed job's model. Binary resource bytes are deliberately not copied into each job: metadata identifies their current SHA-256, and the owned asset endpoint refuses stale requests. A changed installed resource requires a metadata refresh rather than silently passing different bytes.

`GET /api/jobs/:id/hotend` serves completed-job metadata. `GET /api/jobs/:id/hotend/model?sha256=…` serves the exact bounded native STL. Unknown jobs return404; unfinished jobs409; stale/unbound checksums409. A URL never accepts a filename or absolute path. Files must remain inside the configured root, be regular non-symlink final files, and parse as bounded binary or ASCII STL. Invalid declared files surface an error; they are not silently replaced. The size bound is5MiB,100,000 triangles and10,000mm absolute vertex coordinates. Geometry is not recentered, rescaled or repaired.

User vendor resources are searched only when `ORCA_NATIVE_VENDOR_DIR` explicitly points to the native **vendor resource directory**. No native account/configuration files are auto-discovered. A missing setting is reported in the provenance note. This explicit isolation differs from the desktop's implicit user-data search. Older jobs have no identity snapshot: their default fallback is labeled. Old servers without the endpoint retain the bundled web default with an explicit legacy note. Missing/corrupt/changed assets leave exact tool coordinates available with a geometry-unavailable notice.

Evidence:

- Ten independent original-C++ lookup cases cover system ID vs display name, duplicate vendor/model names, resource precedence, empty-model alias, absent vendor models and absent defaults. `scripts/generate-hotend-selection-reference.py` verifies the pinned source and retains source/function hashes in the fixture; it compiles the original lookup functions with a minimal filesystem/config facade.
- Installed native profiles cover at least15 distinct declared hotend resources, including genuine missing-vendor/default behavior. Every served byte and SHA-256 matches the corresponding installed resource. The Vzbot330 system preset resolves its actual `Vzbot/Goliath.stl` with3,208 triangles; the bundled default has560.
- HTTP tests cover ownership, completed-state restriction, identity persistence in multipart and embedded-project jobs, stale hashes, explicit resource roots, traversal, symlinks, size/corruption, binary and ASCII geometry, and defensive catalog output. Fixtures contact only temporary localhost servers.
- Browser/native-helper checks use the retained genuine GUI-exported G-code and real installed GCodeProcessor. They render the3,208-triangle Vzbot asset, change to an older job's560-triangle default, show source notes, and clear previous geometry when the next resource is unavailable. Three existing native-marker/property/profile browser cases remain passing. This is native data/geometry acceptance, not a new paired desktop GUI screenshot claim.

Remaining scope: the desktop's empty-resource procedural-arrow fallback, optional realistic/smooth-normal hotend styles and pixel-exact native GUI placement need separate source/render acceptance. The active flat-normal native mesh path remains covered by the previous original shader/normal reference. No printer connection or physical motion is performed.
