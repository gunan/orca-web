# Native model clipboard and Clone

Baseline: OrcaSlicer 2.4.2, source `8500fcdccaa10b5099ac20d252af3a7c560046f1`. This implements the **model** clipboard. Native settings/layer-row clipboards, operating-system interchange, the exact GUI appearance, and every Clone-adjacent workflow are not certified by this milestone.

## Behavior

Copy captures selected objects or selected parts in model/list order, independently of subsequent source edits. Copy does not change project history. Paste and Clone commit fresh identities and all returned placements in one undo step (followed by a separate step when Auto arrange is selected); cancellation or a stale project cancels the entire operation. Names remain unchanged. Clone selects the final copied batch, matching native ObjectList selection; a single Paste selects every newly pasted member. Ctrl/⌘+C, V, and K follow the native shortcuts and leave text fields/modal editors alone. The existing Duplicate command is an explicit one-copy native clipboard wrapper.

Clone accepts 1–1000 copies, bounded further by geometry, object and worker limits. Part cloning repeats the original clipboard volumes inside one destination object. Same-source/same-linear-transform part pastes keep their native coordinates. Other-source part pastes use native destination-instance bounds and the inverse destination transform, recomputing bounds for each repetition. Browser application preserves source meshes and part settings, adopts destination object settings, and does not pretend an arbitrary nonuniform transform is representable as only an Euler rotation.

The whole-object helper uses the original `Model` mesh centering, native convex hulls, `Polygon::contains`, float grid arithmetic, and C++ `std::sort`. It preserves native grouping, off-plate placement, five-percent-bed fallback, and the later `Plater::changed_objects` grounding rule. For example, the native intermediate off-plate cube offset Z100 on a 200 mm bed is grounded to Z10 for the final 20 mm cube. Original and intermediate matrices are available for diagnostics.

A counterintuitive source behavior is intentionally retained: `get_empty_cells` appends candidate cells outside **each** hull separately. It does not intersect the free-cell sets of all objects. Ties and duplicate candidate entries remain present. Consequently, native repeated cloning can overlap existing geometry. The original-source fixtures cover this behavior rather than replacing it with an invented collision-free layout. Auto arrange is integrated as a separate native arrangement operation after Clone. It creates a second Undo snapshot, matching the original Clone dialog: one Undo restores the pasted positions and a second removes the clones. Fill remains explicitly unavailable pending its separate implementation.

All native millimeter 3MF parts now retain their validated original indexed mesh and build/component matrices, including ordinary meshes without text. Unreferenced raw vertices are compacted without changing referenced coordinates or face order. These data are precision carriers, checked against the authoritative browser triangles. Source transforms update the carrier; topology changes invalidate it. This is necessary for original native instance offsets during grouped Copy/Paste and also avoids a lossy world-mesh reconstruction. Native text/SVG regeneration metadata, painting, original names, filament/part settings, and object-owned brim anchors survive whole-object copies.

Native `copy_to_clipboard` does not copy the object's cut-family identity. The web copy therefore retains processed connector geometry but detaches the clone's family identity and connector flags, with a visible notice. Pasting into a processed cut object invalidates the changed family's correspondence with a notice; the original geometry remains. This explicit integrity rule avoids exporting inconsistent native cut metadata.

Model Cut (Ctrl/⌘+X) now uses this independent clipboard followed by the native deletion/confirmation rules. Undo restores geometry without erasing the clipboard. See [Cut clipboard evidence](NATIVE_CUT_CLIPBOARD.md) for processed-cut families, part deletion and the remaining multiple-confirmation/linked-instance limits.

## API and limits

`POST /api/geometry/clipboard` takes the native geometry request and returns native placement data. It does not take file paths. Models contain bounded indexed vertices/triangles, part kinds, original component matrices and instance matrices. Whole-object requests add `clipboardObjects` and `copies`; part requests also add `pasteParts.destinationId`. The helper accepts one model instance per serialized web group.

The C++ boundary limits total input geometry to 500,000 vertices and triangles, 4,096 objects, 1,024 parts per input object, 4,096 destination volumes for part cloning, two million grid/candidate entries, and 50 million containment visits. Coordinates, affine transforms and clone counts are checked. Float steps that cannot advance throughout their grid range reject explicitly. The service owns request/output byte caps, child timeout, serial queue, cancellation, stdout/stderr draining and cleanup. The client also enforces the two-million-triangle saved-project limit and checks every returned source identity and matrix before applying it.

The browser cannot obtain arbitrary original filesystem paths. `sourceFile` is the available descriptive input identity used for native same-source part-paste matching; same-basename files from different local directories are not a proven GUI-equivalent case. Multi-instance native objects are represented as the web's existing per-instance groups. These limitations remain explicit.

## Evidence

- `tests/unit/native-clipboard.test.js`: immutable snapshots, original naming, fresh IDs, painting/settings retention, all-plate coordinates, cut-family handling, source-frame retention, stale topology rejection, output validation, mode rules and repeated part copies.
- `tests/native/native-clipboard.test.js`: 16 exact comparisons against separately compiled original native methods; malformed/bounded-grid rejections; actual installed 2.4.2 slicing after Copy → web JSON → native 3MF roundtrip. The latter prints the two cube centers `[10,10,10]` and `[31,10,10]`, with both object labels present.
- `tests/fixtures/native-clipboard-reference.json`: inputs and independent C++ expected results, with hashes of extracted original methods. `native/arrange-worker/scripts/build-clipboard-reference.py --source <pinned repository> --build <built arrange directory> --output <directory>` rebuilds that independent reference executable and verifies source hashes. It links native Model/geometry dependencies but excludes the production clipboard helper.
- `tests/native-e2e/native-clipboard.spec.js`: actual browser → production `/api/geometry/clipboard` → native Clone and same-object part Copy/Paste, undo/redo, native project export, and real2.4.2 slicing into two object identities across125layers. No API mocking.
- `tests/e2e/native-clipboard.spec.js`: explicitly mocked transport checks for Copy/Paste, unchanged names, atomic undo, keyboard/Enter behavior, part Clone, unavailable worker, cancelled late responses, and separate Clone/Auto arrange Undo steps. These are UI tests, not native algorithm evidence.

The native comparison uses the current macOS C++ standard library's sorting behavior. Native GUI Copy/Paste captures and cross-platform tie equality remain unverified. This milestone is not a full parity certification.
