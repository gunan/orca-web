# Native text regeneration — M28

The web editor can regenerate an imported native text part with the pinned OrcaSlicer 2.4.2 geometry engine. Native font collections, line height/depth, character/line gaps, boldness/skew, alignment, planar extrusion and Use surface are functional. Text changes preserve the original glyph plane and object transform. Painting on replaced triangles requires explicit consent; cancel leaves the scene unchanged and Undo restores the prior metadata/mesh.

The installed-font catalog reuses existing bundled IDs and adds only server-configured installed font directories. Font selection uses opaque IDs. An unmatched original font requires an explicit selection; there is no silent font substitution. Collection metadata comes from the native font parser. Native text metadata, source precision carriers, JSON save/load, and validated native project export remain supported. New text through the existing general Text workflow still uses its prior implementation; the imported-native edit path is the new native engine integration in this milestone.

## Implementation

- `native/emboss-worker/`: reproducible source/dependency manifest, CMake subset, native glue, license, and explicit build command.
- `server/native-emboss-worker.js`: bounded queue/deadline/process protocol, cancellation, version/mesh checks.
- `server/native-fonts.js`, `server/native-text.js`: private font allowlist and `/api/native-text/{capabilities,fonts,fonts/:id/metadata,generate}`.
- `shared/native-emboss-regeneration.js`: source-frame request and changed-mesh application without detaching native placement.
- `src/NativeTextDialog.jsx`: imported native text editor, real preview, font collections and painting-loss consent.

Native geometry sources are unchanged at commit `8500fcdccaa10b5099ac20d252af3a7c560046f1`. The surface job glue is adapted from the active `EmbossJob.cpp`, using native CGAL patch cutting, ±1 mm projection extension, facing/nearest-patch handling, reflection handling, and the native 0.015 mm overlap. No simplified curved-surface projection was substituted.

A precision refinement computes the native mesh center from Float32 vertices, as `ModelVolume::center_geometry_after_creation` does. Retained native mesh data stays unchanged; only regeneration-frame/fix math is corrected.

## Verified evidence

The independent references are the captured native GUI planar and Use surface `A & B` Helvetica projects already checked into `tests/fixtures`. They were not generated by this worker.

- Planar: **584 vertices and 1,176 triangles**, identical triangle index sequence and bit-identical original raw Float32 vertices. Saved XML coordinate comparison is within 0.00000006 mm.
- Surface: **288 corresponding vertices and 572 triangles**; maximum saved-coordinate discrepancy below 0.000001 mm. Native CGAL can choose different cap diagonals. Tests independently check a bijective vertex correspondence, unchanged oriented boundaries, coplanarity/orientation, and identical covered area for every changed cap patch.
- Actual production slicing after planar worker regeneration and validated JSON/native export: **all 13,743 normalized motion commands exactly match** the original GUI model.
- Changed surface text `AB`: **384 manifold triangles**, successfully exported and sliced by real OrcaSlicer 2.4.2; raised deposition reaches **Z 21 mm**.
- Native Helvetica collection inspection reports six collections with independently expected Regular/Bold entries and 2,048 units/em.

Focused checks: **14 new unit tests**, **12 existing native metadata regressions**, **6 real native kernel/slicing tests**, **4 mocked API browser tests**, and **1 real-worker browser test**. The final real-worker browser run also verifies the installed OrcaSlicer 2.4.2 service and validated native export. Production build passes. No test was skipped or marked green for an unimplemented feature.

## Failed comparison retained

An unchanged regenerated surface model produces the same 12,030 normalized motion-command count, but its exact sequence differs from the saved GUI reference. The captured probe's first mismatch is command 10,979 on layer Z20.6: reference travel starts at `X105.319 Y111.798`, regenerated travel at `X105.396 Y111.85`. Cap retriangulation changes a later path start. Geometric coverage is independently equivalent, but **exact surface command-stream acceptance has not passed**. The original probe files remain in staging `test-results/regenerated-slice/`, with reference files from the M24 retained-fixture comparison. This was not reclassified as exact equivalence.

## Remaining acceptance

Per-glyph layout still needs the native slice/arclength/tangent algorithm and GUI reference fixtures. New native text creation, native font-style management, native placement/rotation/distance gizmos, and native SVG regeneration remain incomplete. The current editor does not expose placeholder controls for these operations. Native GUI reapply of the newly regenerated exports remains pending while the desktop is locked. No physical printing, printer contact, pixel equality, complete feature parity or universal native-path equivalence is claimed.
