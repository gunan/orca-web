# Source-backed calibration foundation

This implementation supports **temperature towers, pressure advance seam towers, generated PA lines and four-layer PA pattern batches, input-shaping frequency towers and input-shaping damping towers, cornering towers, VFA towers, maximum volumetric flow towers, retraction towers, and all four native flow-ratio specimen sets** using bundled models and source-generated PA paths pinned to installed OrcaSlicer **2.4.2**. It generates offline calibration output and can save an explicitly selected flow specimen or entered temperature/PA/retraction/maximum-flow measurement as a new durable custom filament preset. It does not contact a printer or measure a printed result. Automatic calibration, hardware workflows and unsupported setting combinations remain unavailable. This is partial native calibration coverage, not full calibration/UI parity.

## Pinned source and behavior

All source references are pinned to commit `8500fcdccaa10b5099ac20d252af3a7c560046f1`, the official `v2.4.2` tag. OrcaSlicer is AGPL-3.0; its license is retained in [ORCASLICER-LICENSE.txt](../native-schema/ORCASLICER-LICENSE.txt).

- [Plater.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L12907) supplies PA tower settings and the `ceil((end-start)/step)+1` height rule. [Temperature preparation](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L13138) supplies 10 mm labelled blocks beginning at 500 °C, 5 °C increments, nozzle scaling and scoped native overrides.
- [calib_dlg.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/calib_dlg.cpp#L346) supplies native temperature defaults and range validation. The supported web subset additionally requires 5 °C-aligned endpoints and a model that fits the selected printer.
- [calib.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/calib.cpp#L11) supplies the PA wall-speed calculation from current outer-wall speed and filament volumetric limit. [Flow.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/Flow.cpp#L21) supplies the automatic 1.125× nozzle line width.
- [GCode.cpp calibration switch](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode.cpp#L4690) applies PA as `start + floor(layerZ) × step`. Its [layer interpolation](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode.cpp#L7295) defines temperature steps over actual sliced layers, including float arithmetic and the first-two-layer behavior.
- [GCodeWriter.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCodeWriter.cpp#L370) defines PA commands for Klipper, RepRapFirmware, Repetier and Marlin/Bambu flavors, including four-significant-digit values.

The installed CLI has no `Calib_Params` flag. The web pipeline therefore converts the same bundled `.drc` resource with the real CLI, clips/caps its triangles, resolves and applies the source-derived native settings, slices normally, and inserts the calibration commands into actual G-code at the native layer-change anchor. PA line mode uses the bundled native preview asset and replaces its ordinary sliced body with the pinned source's generated line/tab paths; it does not print the displayed preview mesh. Temperature/PA/input-shaping/cornering insertion preserves motion/extrusion; speed modes change effective outer-wall feedrates, and retraction changes paired retraction/wipe/unretraction E. The processor rejects missing anchors, wrong engine versions, inconsistent layer counts, descending plate/layer sequences and repeated application. For input-shaping spiral towers, the one final taper pass may repeat the last Z marker; all other repeated Z markers are rejected.

Native resource conversion is isolated and accepts eight whitelisted tower paths, one whitelisted PA line preview path and four whitelisted flow-ratio 3MF paths. PA patterns use a separate source-generated handle identifier; no arbitrary resource path is accepted. Temperature cuts use a 0.001 mm inset and sub-micron intersection welding to avoid float32 collapse of labelled-block cap triangles. Caps retain holes and all boundary vertices. This numerical implementation differs from native cutting internals; no byte-identical native GUI geometry claim is made. PA automatic/adaptive commands are disabled in the generated filament configuration so they cannot overwrite the injected schedule. The nominal PA end can be exceeded at the final integer-height boundary, following the native height/schedule rules.

## Integration contract

`createCalibrationSessions({binary, resourcesDir, catalog})` returns `{router, validateUpload, validateProject, shutdown}`. Mount its router at `/api/calibrations` and include `shutdown()` in application shutdown.

`POST /api/calibrations/prepare` accepts printer/process/filament IDs and only the parameters defined for the chosen mode. Temperature/PA/VFA/max-flow/retraction use `mode,start,end,step`. Input-shaping frequency uses `mode,testModel,shaperType,frequencyStartX,frequencyEndX,frequencyStartY,frequencyEndY,damping`; damping uses `mode,testModel,shaperType,frequencyX,frequencyY,start,end`. Cornering uses `mode,testModel,start,end` and adds the `scv` model choice; its firmware parameter kind is resolved server-side from the printer preset. `testModel` is `ringing` or `fast`; `shaperType: auto` selects the first native choice for the firmware. It resolves native presets server-side and returns `{calibration:{...normalizedParameters,token}, plan, objects, expiresAt}`. The dialog accepts optional `printerConfig` to display firmware-specific shaper choices; the server always validates the resolved native flavor. The dialog's `onCreate(response)` callback receives that response. Store the calibration object in the web project, replace the current scene with its returned object list, clear ordinary process overrides, and require regeneration after geometry/preset changes.

Tokens bind the normalized parameters, all three preset IDs, a digest of the resolved native preset configuration and the exact baked binary STL bytes. The cache retains at most 32 sessions for 24 hours (and up to 64 idempotent result saves per session) and is intentionally ephemeral. Expiry, eviction or restart requires regeneration. Only one preparation can run at once; overlapping attempts receive HTTP 429. Client disconnection and application shutdown abort native conversion. No client-supplied plan, resource path, command or generated setting is trusted.

For STL job submission, parse the calibration field and call `validateUpload({calibration, ids, inputPath, overrides})`. It rejects changed settings, preset content, parameters, geometry, non-STL input or stale tokens, returning the trusted `{plan, selection}`. Apply `applyCalibrationOverrides(selection, plan)` and force `preservePosition: true`. After native slicing, call `applyCalibrationGcode(rawGcode, plan)` and save its returned G-code before marking the job ready. Preserve cancellation checks and atomic output replacement around this step. Ordinary jobs should remain on their existing path.

Flow ratio and PA patterns use `plan.inputFormat: 3mf`. Preparation retains the complete native project/3MF bytes in the server cache and returns only its validated objects/plan. `validateProject({calibration,ids,objects})` validates the token, current preset content, exact baked object geometry, order, labels, visibility, native grouping and per-object configuration, then returns trusted `{bytes,project,settings,summary,warnings,ids,selection,plan,calibration,expiresAt}`. `selection` contains native preset configurations; `ids` contains the real catalog IDs. The dedicated `/api/jobs/calibration` integration accepts those three request fields and enqueues the trusted cached bytes without additional load-settings/filament flags. It must still call `applyCalibrationGcode` for native-output verification and the meaningful specimen summary before marking ready.

For flow, `POST /api/calibrations/result` accepts only `{token,objectId,name}`. Temperature, PA, retraction and maximum-flow accept `{token,value,name}`. The server identifies the actual generated specimen, verifies the unchanged source preset, derives the result from its source-bound formula, and saves a new custom filament with the original filament as its template, compatible with the selected printer. It returns `{preset,result}`; repeated identical token/object/name submissions reuse the same saved preset. The original preset is preserved. `CalibrationResultDialog({open,onClose,calibration,plan,onSaved})` requires explicit user selection; `onSaved` receives that result so the caller can refresh/select the new filament. Custom preset storage survives server restart; preparation tokens and result retry caches do not.

## Executed acceptance and limits

Focused unit checks cover native parameter rules, scope-preserving generated overrides, flow-based PA speed, firmware command formatting, float layer interpolation, output rejection, clipped cap winding/volume, retained holes and bed placement. Session HTTP tests use an explicit model fixture to test token/configuration/STL binding, cache eviction/expiry, malformed requests, preparation concurrency and cancellation. They do not certify native geometry.

Twenty separate strict native tests exercise the real HTTP preparation endpoint, token validation, source model conversion, preset/configuration application, real slicing and final layer commands. The 230→225 °C reference tower has 6,436 closed triangles, measures approximately 44.499×10.000×19.998 mm and produces 100 layers with the actual M104 schedule. The PA 0→0.004/0.002 fixture has 52 closed triangles, measures 70×70×3 mm and produces 15 layers with changing M900 values. The input-shaping frequency fixture uses the native fast tower: 1,344 closed triangles, approximately 40.020×40.019×60.000 mm. The damping fixture uses the native ringing tower: 3,504 closed triangles, 120×120×60 mm. Both slice to 300 original layers plus one closing spiral pass; tests assert meaningful `M593` X/Y frequencies and damping changes, native spiral/acceleration configuration, and repeated final schedule values. The temperature/PA/input-shaping tests verify that postprocessing leaves the native motion/extrusion commands unchanged and that the generated upload remains valid after the client bed-drop operation.

The generation/result dialogs have sixteen isolated browser checks with mocked preparation responses for request/callback wiring, explicit unsupported preset combinations, preparation failures, separate frequency/damping fields, model selection, firmware-specific shaper choices, shared RepRap axes and legacy-firmware rejection, cornering model choice and printer-dependent cornering defaults/units, flow method/pattern selection, explicit specimen selection, result errors and mutation dismissal protection, plus VFA speed-band defaults and maximum-flow units, settings and timing/flow-limit information. Thirty-nine focused unit checks and fourteen HTTP session checks cover parameter/geometry/schedule validation and token lifetime/binding; fixture tests are distinct from twenty actual native slicing checks. These supplement, rather than replace, the real-native tests.

The [native calibration switch](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode.cpp#L4720) defines zero-based first/second-layer initialization, continuous float32 interpolation and Klipper minimum-cruise-ratio commands. [GCodeWriter.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCodeWriter.cpp#L395) supplies `SET_INPUT_SHAPER`/`M593`, axis behavior, two-decimal frequencies, three-decimal damping and zero-value no-ops. RepRap's `DAA` choice likewise emits no algorithm parameter, matching this native writer. Firmware support must exist: Marlin 2.1.2+, Klipper 0.9.0+, or RepRapFirmware 3.4.0+ with the selected algorithm. Firmware version is not detected by this offline application.

[SpiralVase.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode/SpiralVase.cpp#L123) adds a final taper pass for relative extrusion, copying non-motion commands. The web processor therefore uses the native footer's original layer count for interpolation and repeats the final command on that pass, while preserving all native moves and extrusion. Both layer-count sources must agree with the permitted closing-pass structure. Preset end G-code remains intact, including native firmware resets after the print. Unit checks cover Klipper, RepRapFirmware and Marlin command dialects; the new strict native fixtures use the default Prusa MK4 preset's Marlin 2 dialect. No physical firmware behavior is certified.

## Cornering source and limits

[Plater::Calib_Cornering](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L13521) defines ringing/fast/SCV-V2 models, 2,000 mm/s² acceleration, a 200 mm³/s filament allowance, disabled cooling slowdown and a request to disable input shaping. Positive Marlin 2 `machine_max_junction_deviation` selects a 0→0.25 mm default (maximum 0.3 mm); other presets select 1→15 mm/s jerk (maximum 100 mm/s). The native [dialog](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/calib_dlg.cpp#L1294) and [writer](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCodeWriter.cpp#L255) define those modes, clamps and firmware commands. A zero JD or jerk below 0.01 produces no command, retaining the existing firmware value as in the native writer. Repeated identical web commands can occur; no byte-identical writer-cache behavior is claimed.

The processor checks the actual native object-printing body for commands that would overwrite the active cornering parameter, and rejects a conflicting preset before producing a ready calibration. Marlin JD (`M205 J`) is independent of its emitted classic X/Y jerk settings, which are preserved. Start and end firmware resets remain intact. The native input-shaping-disable request remains subject to the selected firmware and the engine's machine-envelope emission rules; this offline application does not verify firmware execution.

Two strict native fixtures resolve the bundled default Prusa MK4 selection and explicitly configure its Marlin 2 JD maximum positive versus zero. The JD fast tower has 1,344 closed triangles and 300 schedule layers plus taper pass. The classic-jerk SCV-V2 tower has 2,368 closed triangles, measures approximately 81.964×67×100 mm and has 500 schedule layers plus taper pass. Tests confirm source-based native configuration, effective varying `M205 J`/`M205 X/Y` commands, no opposing commands, repeated final schedule values and unchanged motion/extrusion. Other firmware dialects have unit coverage, not real firmware certification.

Because cornering changes motion timing after slicing, the pre-calibration printing-time comments and time-derived `M73` progress updates are removed. The output explicitly marks time estimation unavailable. Native filament/material estimates and all motion/extrusion remain unchanged. Recalculating calibrated native time estimates is still missing.

## Flow-ratio source and limits

[Plater.cpp:adjust_settings_for_flowrate_calib](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L12975) defines the labelled native resource names, nozzle scaling, ten-layer height (first layer plus nine nozzle/2 layers), two bottom/five top layers, 35% infill, 1.2× nozzle top/solid line widths, flow-limited speeds and per-object `print_flow_ratio`. The internal `calib_flowrate_topinfill_special_order` option is preserved. The native [flow dialog](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/calib_dlg.cpp#L1463) supplies the four methods and Archimedean Chords/Monotonic top-pattern choices.

| Method | Native specimens | Label interpretation |
| --- | ---: | --- |
| Coarse pass 1 | 9 | −20% through +20%, in 5% increments |
| Fine pass 2 | 10 | −9% through 0%, in 1% increments |
| YOLO recommended | 11 | −0.05 through +0.05, in 0.01 increments |
| YOLO perfectionist | 16 | −0.04 through +0.035, in 0.005 increments |

For percentage passes, the object multiplier is `1 + label/100` and the saved filament ratio is `originalRatio × multiplier`. For YOLO, the object multiplier is `(originalRatio + label)/originalRatio` and the saved ratio is `originalRatio + label`. Result saving follows this extrusion-equivalence formula; the web result dialog is an explicit manual workflow, not a claim of matching a native automated calibration UI. Every generated result must remain in the native filament ratio range above 0 through 2.

The installed resources include bounded ZIP64 archives; the shared importer validates and decodes them, retaining the original specimen names and topology. Objects remain separate, with their source-defined configuration, and are exported as a native project rather than flattened STL. The original specimen group layout is centered on the bed; XY enlarges only when nozzle/0.6 exceeds 1.2, and each specimen scales in Z. A 2 mm surrounding margin and the whole layout must fit the supported rectangular bed. Native automatic nesting and sequential-print clearance certification are not implemented here.

Four strict native fixtures prepare, bind, export and slice the actual 9/10/11/16-object sets using the bundled Prusa MK4/0.4 mm selection. They compare measured outer-wall extrusion per millimetre at the same layer across every specimen against the intended multiplier, within 0.3% tolerance for emitted E precision. All objects are closed. Each test explicitly chooses a negative labelled result, saves its new custom filament, reloads storage and verifies its flow ratio and printer compatibility. These are commanded extrusion measurements, not physical printer measurements. Unlike cornering postprocessing, flow settings are applied before native slicing, so native motion, extrusion and time/material estimates remain intact; output verification adds only a provenance comment.


## VFA source and limits

[Plater::calib_VFA](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L13351) supplies the bundled 300 mm VFA model, clipped height `5 × ((end−start)/step + 1)`, one spiral wall, one bottom layer, no top/infill, 3 mm outer brim, disabled overhang speed/resonance avoidance, and zero minimum layer-cooling time. The selected layer height and spiral smoothing remain unchanged. The source [dialog](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/calib_dlg.cpp#L641) defaults to 40→200 mm/s in 10 mm/s steps. The web workflow requires start > 10, end ≤ 1000, positive step and at least two bands; it rejects requests exceeding the source model height or selected build volume. The general manifold plane cutter retains the native curved surface and validates its closed cap.

The native [GCode calibration switch](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode.cpp#L4700) requests `round(start + floor(print_z/5) × step)`. The web schedule uses the native output's reported layer Z; rounding at internal floating-point layer boundaries is not independently certified against GUI calibration output. As in that formula, the exact final 5 mm boundary can request one step beyond the nominal end. The native [extrusion speed pipeline](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode.cpp#L6543) subsequently applies the first-layer speed, gradual slowdown layers and volumetric cap.

The CLI does not expose calibration state. A 3MF height-range experiment was rejected by native spiral-vase validation because it creates multiple print regions. Instead, the server slices at the maximum requested band speed. Postprocessing reduces only positive-extrusion outer-wall feedrates to the source schedule, retaining each original native speed cap. The monotonic first-layer ramp is evaluated before that cap; native first-layer speed is preserved. Geometry, E values, travel/retraction speeds and firmware settings stay intact. Modal feedrates are restored for non-wall moves, and both absolute and relative E are tested. Missing role/object markers, wrong native configuration/version and non-mm/per-minute units are rejected. Pressure equalizer, adaptive PA, nonzero small-perimeter threshold and rafts are explicitly unsupported because they require additional speed-dependent behavior. Native timing comments and M73 time-progress are removed; material estimates remain available. This offline mode does not infer a best speed or save a measured result.

Three actual-native tests exercise unchanged bound STL sessions using the installed Prusa MK4 default selection. The 40→80/20 fixture produces a closed 6,110-triangle, 15 mm native model and 75 layers plus closing spiral pass. For ordinary settings, a 2 mm³/s filament cap and a five-layer gradual speed ramp, all **7,832 outer-wall moves per fixture** match geometry, E and effective F against four independently sliced constant-speed native reference files (40/60/80/100 mm/s), within 0.002 mm/min emitted-feed precision. Changed geometry/parameters are rejected. These comparisons verify the generated command stream, not physical velocity, artifacts, acceleration behavior, or byte-identical native GUI calibration output.


## Maximum volumetric flow source and limits

[Plater::calib_max_vol_speed](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L13218) uses the installed 100×180×280 mm SpeedTestStructure model, reducing only X when `(bedWidth−10)/modelWidth < 1`. It sets 1.75× nozzle outer-wall width, 0.8× nozzle layer height, raises the printer's maximum layer height if needed, uses a 5 mm outer/inner brim, a continuous spiral wall without bottom/top/infill, zero minimum cooling time, and a 200 mm³/s filament allowance. Pressure equalizer and resonance avoidance are disabled. The initial layer height, first-layer speed and spiral smoothing remain selected-preset behavior. The source height is `(end−start+1)/step`, and a closed manifold cut retains the native shape. The X-only compression and actual source geometry must fit the selected rectangular bed.

The [dialog](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/calib_dlg.cpp#L536) defaults to 5→20 mm³/s with a 0.5 mm³/s-per-mm step. Native [Flow::mm3_per_mm](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/Flow.cpp#L219) stores width/height and its rounded-rectangle area in float32. The calibration multiplies that area by the current filament flow ratio, then converts input flow into linear-speed start/step. The native [calibration switch](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode.cpp#L4705) requests `round(startSpeed + layerZ × stepSpeed)`.

The web scheduler shares VFA's maximum-speed native baseline and preserves its independent native speed caps, first-layer behavior and gradual ramp. The final printed layer can exceed nominal end flow because of the native height rule and layer quantization. Inputs are bounded to positive flow through 200 mm³/s, the source/build height and representable native speeds; requests with fewer than two layers fail clearly. Rafts, adaptive PA and nonzero small-perimeter threshold remain unsupported. Native output/configuration, exact generated STL and current presets must match the session. The native 200 mm³/s cap remains effective even if a final requested boundary exceeds it. Geometry/E/travel/retraction remain unchanged; time comments and M73 time-progress are removed, and material estimates remain available.

Four real-native fixtures compare every scheduled positive outer-wall move against independently sliced constant-speed reference files. The standard 0.4 mm fixture has 5,592 closed triangles and 3,440 checked moves; the 80 mm bed-width fixture verifies the native 0.7 X scale and 2,859 moves; the 0.6 mm nozzle/0.92 filament-ratio/five-layer ramp fixture checks 2,504 moves; a 199→200 mm³/s request checks the native ceiling across 2,493 moves on a 5,516-triangle model. The reference sets contain 9, 9, 6 and 8 native speed slices respectively. XYZ/E and effective feedrates match within 0.002 mm/min emitted-feed precision, including closing passes. These are command-stream comparisons, not physical volumetric measurements or native GUI calibration captures. Failure-height measurement remains manual; the explicitly entered usable flow limit can be saved as a new filament preset.

## Retraction source and limits

[Plater::calib_retraction](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L13293) supplies the native `retraction/retraction_tower.drc`, two walls, three bottom layers, no top/infill, aligned seams, inner/outer wall order, disabled firmware retraction/resonance avoidance and float32 nozzle-dependent layer heights of 0.05/0.1/0.2 mm. The source cut height is `1.4 + (end−start)/step − 0.0001`. The general cutter now welds the actual Float32 output, removes collapsed faces and splits collinear boundary edges; the exact 3.3999 and 21.3999 mm cuts remain closed without shifting the plane. The plan preserves the source's float32 layer height, and the scheduler reconstructs that fixed-height layer index from validated native Z markers to avoid rounded-Z floor errors at 1.4 mm boundaries.

[GCode.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode.cpp#L4710) changes the writer's retraction length to `start + floor(max(0, print_z−0.4)) × step` after layer-change macros. Retractions occurring before that anchor retain the preceding value, and their later unretraction restores the amount actually withdrawn. [Native wipe behavior](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode.cpp#L313) limits withdrawal during wiping by the physical wipe path/speed and moves remaining withdrawal before the wipe. [GCodeWriter.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCodeWriter.cpp#L1004) and [Extruder.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/Extruder.cpp) define the accumulated retracted state and matching unretraction.

The server slices once using the largest required length, then rewrites actual explicit E commands and preserves deposited extrusion, XYZ paths and effective feedrates. Relative and absolute E with G92 resets are supported. Native comments, expected preset values, fixed layer markers and explicit millimetre E commands are required; unknown retractions or missing wipe markers fail closed. Zero-length ranges with active Z hop, layer-cooling slowdown, pressure equalizer, adaptive PA, nonzero extra restart length, rafts, spiral mode and layer-change extrusion macros are explicitly unsupported. Initial or requested zero lengths require zero hop because native hop geometry is length-dependent. Time estimates and M73 time progress are removed; native material estimates remain. Native height rounding can add a final value beyond the nominal end. Defaults are 0→2 mm in 0.1 mm steps; generated presets with incompatible settings fail with a concrete reason.

Three real-native fixtures exercise HTTP preparation and unchanged token-bound uploads on a closed 2,196-triangle tower cut at exactly 3.3999 mm: positive lengths with wipe/hop, zero lengths with wipe/no hop, and absolute E without wipe. Each produces 39 balanced retraction cycles. Every original XYZ/feed/deposited-E movement is preserved (2,462 / 2,393 / 2,308 checked movements). Both wipe fixtures match all 39 wipe cycles, including before-wipe withdrawal and each wipe segment's E, to independently sliced constant-length native references within 0.00012 mm emitted E tolerance; every scheduled length has a reference. The absolute-E fixture additionally matches the per-layer native deposited XYZ/E/F segments independent of island order and verifies native pure retraction amounts. Repeating the *same* native configuration experimentally reordered some tower islands, so order-sensitive whole-file comparison is not used as the oracle. These tests prove commanded extrusion, not physical stringing or GUI-calibration byte identity. A manually entered retraction length can be saved as a new filament override.

## Explicit measured-result persistence

`shared/calibration-results.js` maps an explicitly entered value to source-defined native filament keys. Temperature sets `nozzle_temperature` and `nozzle_temperature_initial_layer`; PA sets `pressure_advance`, enables `enable_pressure_advance` and disables `adaptive_pressure_advance` so the saved value is fixed; retraction sets the nullable `filament_retraction_length` override; maximum flow sets `filament_max_volumetric_speed`. These native fields are defined in pinned [PrintConfig.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/PrintConfig.cpp). The web result dialog is a manual convenience workflow, not a claim that native temperature/retraction dialogs provide identical result entry.

The input starts blank and must be a finite number within the cached plan's tested range (the actual bed-limited final value for PA lines); temperature requires whole degrees. The interface describes all changed settings before saving. It never chooses a measurement from preview, infers failure height, or applies an unrequested flow margin. The server rejects extra fields, substitute specimen IDs, expired sessions and changed source presets, uses the original filament template and printer compatibility, preserves the original preset, and deduplicates concurrent identical normalized value/name retries. Numeric and string representations of the same value share an idempotency key. The new custom preset survives catalog reload; the ephemeral calibration token does not.

Five new unit tests and five HTTP tests cover all four mappings, bounds, malformed values, changed/expired sessions, request isolation and concurrent retries. Five additional browser checks require explicit entry, show precise setting effects, reject out-of-range values, verify the callback and keep unsupported result modes disabled. Four real-native tests prepare actual bundled geometry, save explicit values (225 °C, PA 0.002, retraction 0.4 mm and maximum flow 6 mm³/s), reload durable custom storage and use each new filament for an ordinary native cube slice. All native output configuration fields match; effective `M109 S225`, `M900 K0.002` and 0.4 mm unretraction commands are also checked. These are persistence and command checks; no physical specimen has been measured or printer contacted.

Full native calibration acceptance still needs native GUI-generated reference projects/toolpaths, more nozzles/presets/firmware flavors, physical measurement, automatic calibration and hardware-specific workflows. The supported scope is one unchanged tower/PA-line preview asset or one unchanged native flow specimen set on one rectangular plate, or a PA pattern batch across automatically added rectangular plates, with one extruder. It does not provide a defensible percentage of native calibration parity.

## Pressure-advance line generation

[Plater::calib_pa](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L12622) displays the native `pressure_advance/pressure_advance_test.drc` asset. The [GCode PA_Line branch](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode.cpp#L3246) bypasses ordinary object processing and generates its own toolpath. The web implementation follows that branch, retaining the real native-expanded printer/filament preamble and end templates while replacing the ordinary preview-asset body with actual calibration moves. Prepare therefore shows the original preview geometry; Preview shows the generated paths. These are explicitly different views of the same native workflow.

[CalibPressureAdvanceLine](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/calib.cpp#L444) defines the prime/anchor lines, 20 mm slow ends, up-to-40 mm fast middle, 3.5 mm spacing, optional filled two-perimeter tab and native printed digits. Line count is `ceil((end−start)/step)+1`, limited by `floor((bedHeight−10)/3.5)`. For nozzles below 0.51 mm, line width is 1.5× nozzle; otherwise 1.05×. The initial height comes from the selected process. Fast speed follows the native volumetric calculation and integer truncation; slow speed is at least 10 mm/s. The source uses object flow ratio for the test lines/digits but filament flow ratio for the tab; this difference is retained. Native glyph travel/retraction changes modal feedrate, also retained. Pressure commands, acceleration and jerk limits follow the source firmware writer.

Native calibration start templates use bed bounds inset by 25 mm for `first_layer_print_min/max/size` and disable first-layer scanning. Constant indexed expressions and legacy placeholders are rewritten before native template expansion. Native PA line generation bypasses `process_layer`, so end-template `layer_z` is the generated final height, `layer_num` is −1 and `max_layer_z` is zero. Carrier-only layer macros are replaced with the native CLI's required relative-E reset or empty absolute-E form, then removed with the carrier body. The final output resets absolute E before custom end commands, retracts without inventing a wipe path, and removes stale carrier time/material/progress estimates. Its summary reports generated path filament length with explicit exclusions for start/end purge and restart extras.

Requests use `mode: pressure-advance-line`, `start`, `end`, `step`, and boolean `printNumbers`; defaults are 0→0.1 by 0.002 with numbers. The same exact asset/preset/token binding applies. Width must exceed 80 mm, bed height exceed 50 mm, at least two lines must fit, initial height must be above zero through 0.4 mm and below the line width, and every generated extrusion must fit the bed/build height. Supported scope is one extruder on a rectangular non-Bambu bed. Firmware retraction, unrepresentable five-character labels, reserved boundary comments, unsupported start/end context expressions and coordinate transforms fail clearly. Context-dependent filament start/end templates remain unsupported. Saving a user-entered PA line result uses the actual final printed PA bound, enables fixed PA and disables adaptive PA in a new compatible filament preset.

Ten dedicated unit checks include three independent C++ source fixtures of **324 / 2,660 / 90 ordered writer calls**, normal/legacy macro context, limits, rejection, output replacement, absolute E, result bounds and firmware syntax. The fixture generator embeds unmodified pinned C++ calibration methods with a small configuration/writer recorder; its [provenance and reproduction instructions](../../tests/fixtures/pa-line/README.md) distinguish source evidence from engine evidence. Two actual-native tests prepare the installed 2,532-triangle resource, validate unchanged sessions, run native 2.4.2 slicing, compare every generated XYZ/E/F/PA command against the 324-call labelled and 90-call absolute-E source fixtures, check Prusa mesh-area/end-lift expansion, parse preview layers, and save a compatible fixed-PA result. They verify **255 / 54 generated moves**. Two new browser dialog checks exercise numbers/submission and visible unsupported templates; a result dialog check requires explicit PA entry. All pass with no skips.

A native GUI export comparison could not run because macOS was locked. Therefore these fixtures do not establish native GUI byte identity or physical print behavior. Early probes exposed CLI validation requiring a relative-E layer reset and forbidding it for absolute E; the carrier-only macros now respect both. The preview parser deliberately records the purge section separately, so native tests distinguish it from the one/two generated print layers. An initial C++ recorder incorrectly declared the float-area Flow result as float; review against Flow.cpp corrected its return type to double before fixtures were accepted. The JavaScript extrusion calculation and corrected source fixtures agree. Automatic pressure-advance calibration remains unimplemented.


## Pressure-advance patterns and speed/acceleration batches

[Plater::_calib_pa_pattern](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L12647) builds generic 5×5 mm handle cubes and four custom layer scripts. The bundled historical `pa_pattern.3mf` is not this algorithm's geometry source. The web implementation constructs the same handle dimensions, source-defined process overrides and [CalibPressureAdvancePattern paths](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/calib.cpp#L580): first-layer three-perimeter frame and filled label tab, three-wall chevrons, PA labels plus flow/acceleration labels, upper-layer acceleration/flow trick lines, native Z-hop/retraction and E resets. First width is 1.4× nozzle, subsequent width 1.125×, and height is first-layer height plus three regular layers. PA values use the source's `ceil((end-start)/step+1)` count, including a possible final value above the nominal end; result entry is bounded to the actual generated last value.

Requests accept `mode: pressure-advance-pattern`, `start`, `end`, `step`, `speeds` and `accelerations`. Defaults are 0→0.08 by 0.005. Empty lists use native flow-limited speed and outer/inner/default acceleration fallback. Explicit speed/acceleration arrays produce their Cartesian product in source order, with per-object overrides. Inputs are bounded to four unique speeds and four unique accelerations; each complete pattern must fit a rectangular plate, and additional plates are created as needed. Complete extrusion footprints, including labels and handle cubes, must remain inside the build volume without overlap. Placement uses a bounded grid rather than native polygon nesting. The full batch is limited to sixteen combinations and therefore at most sixteen plates. One extruder, explicit retraction, zero extra restart length and non-Bambu machines are supported. Unsupported templates, layer heights, malformed labels, oversize ranges or hardware combinations fail before a calibrated scene is returned.

The four generated Custom events are embedded in the trusted native 3MF **before** slicing. Installed OrcaSlicer processes the actual handle geometry, templates and custom moves. Its native time/material estimates remain available; no post-slice path replacement invalidates them. Output validation finds every pattern/layer marker and compares all effective XY/Z/E/feed/PA/acceleration/reset commands. Native feed deduplication and inserted M73 progress are tolerated through modal normalization; changed motion, missing layers or substituted pressure commands are rejected. Early probes exposed feed deduplication, including feed inherited across batch boundaries; validation now reads the actual prior feed, rather than requiring byte-identical strings.

Seven new unit checks cover two independently compiled C++ source fixtures (**824 / 2,932 ordered calls**), settings, batch ordering/bounds, native defaults, unsupported cases, output tampering and measured PA results. [Fixture provenance](../../tests/fixtures/pa-pattern/README.md) distinguishes the stubbed C++ recorder from installed-engine evidence. Three strict real-native tests prepare, bind, export, re-import and slice a relative-E single pattern, an absolute-E single pattern and a 2×2 speed/acceleration batch. All have four actual native layers and **644 / 2,281 / 2,578 generated moves** respectively. Both single cases compare every generated command to the independent source fixture after translation; the batch verifies all four complete paths. Each saves an explicitly entered compatible fixed-PA filament preset. Two additional browser dialog cases cover typed batch input and visible fit failures, and one result-dialog case requires explicit PA entry. Native GUI export equality and physical outcomes remain unverified.

## Complete calibration project downloads and persistence limits

For token-bound native-project calibrations (flow specimens and PA patterns), `POST /api/calibrations/project` accepts `{calibration, ids, objects, plateId?, allPlates?}` and returns the server's cached complete 3MF bytes (all plates by default, or the selected complete plate when `allPlates: false`) with `Cache-Control: no-store`. It reuses the slicing validator: session token and parameters, all three selected preset IDs, resolved preset content, object identity/order/native settings and exact baked geometry must still match. It accepts no replacement process settings, client script or supplied plan. Expired, unknown or restarted sessions and any tampering fail with an actionable regeneration message. The app routes native export to this endpoint while that calibration is active and never falls back to exporting its handles as a complete test.

Normal `.orca-web.json` saving remains a scene save. It retains the calibration request/token and displayed objects but does not embed trusted server cache bytes or the PA layer scripts. A visible save notice explains that sessions expire after 24 hours or server restart and that the user should export native 3MF now, or regenerate before later slicing/export. Completed custom result presets persist independently of the token. Generated absolute commands remain server-side in the original editable calibration scene, so editing objects cannot silently preserve detached pattern paths; edits invalidate that calibration association. A downloaded complete native project contains fixed absolute commands. Import recognizes the four-layer pattern markers and retains a deterministic snapshot of geometry/native object settings, complete native settings, ordered plates and layer scripts. Preparation rejects a missing or stale binding, changed geometry/settings/plates, replacement catalog presets, or correction decisions that change its settings, with restore-or-regenerate guidance. Embedded unchanged projects can be re-exported and re-sliced. Shared JSON roundtrips retain this binding. This is accidental-edit detection, not authentication of arbitrary client metadata or proof that an imported user-authored script is a calibrated source result. Ordinary Custom G-code without generated-pattern markers retains its existing semantics.

Four binding unit/service checks cover unchanged JSON roundtrip, incomplete markers, transforms, native settings, plate/script changes, catalog replacement and ordinary custom-script behavior. Three actual-native PA tests now re-import the downloaded project through the native service, prepare it unchanged using embedded settings, and slice those re-exported bytes before matching source commands. Two additional HTTP tests exercise cached flow transport, unknown/expired tokens, shutdown, parameter/ID/geometry/source-preset tampering and unknown fields. Their three-byte cache fixture is explicitly a transport mock, not valid model evidence. Real PA native tests verify exact cached download bytes and re-import all four command layers; real flow tests verify object-specific ratios survive complete project download/re-import. Three full-app browser harness checks download/re-import a valid four-layer fixture, surface expiry without ordinary-export fallback, and save JSON with the token-limit notice. Mock browser endpoints are not counted as native engine or physical evidence.

## Automatically added pressure-advance pattern plates

[Native Plater creates missing plates after arranging complete pattern footprints](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L12755), then [merges four generated command layers only for objects on the current plate](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L12849). The web batch now follows that lifecycle. Every speed × acceleration combination has a stable plate assignment and its complete footprint is checked against the rectangular bed and other patterns on the same plate. The placement algorithm remains a bounded grid, not the native arranger.

Preparation returns safe plate IDs/names and geometry for the browser, while complete scripts and complete whole-project/per-plate native archives remain server-side. Slicing sends **all** bound objects plus the chosen `plateId`; validation detects edits even to inactive plates and uses only the corresponding trusted archive/plan. `Export plate as 3MF` returns that one complete plate. `Export native project` retains all plates and all four command layers on each. Session lifetime and restart behavior are unchanged.

Imported complete pattern archives use binding version 2: changing the active plate or selection is allowed, but all geometry, plate assignments/order, native settings and scripts remain fingerprinted. Unknown plates, edited inactive objects, moved handles, modified scripts, new/deleted plates and replacement preset settings reject with regenerate guidance. Legacy version-1 scene bindings retain their original validation rule. These fingerprints protect workflow consistency; they do not authenticate arbitrary user-authored G-code.

Three unit/service checks cover complete footprint placement, per-plate archive origins, selection and stale-edit rejection; three HTTP checks cover complete-scene tokens, full/selected exports and expiry/unknown tokens. One strict installed 2.4.2 test generates an eight-pattern batch on two plates (6 + 2), downloads/re-imports the full project, then slices each selected plate: four native layers each and **18,200 verified source-generated moves** total. Every command for the 80 mm/s, 1,000 mm/s² pattern also matches the existing independent compiled C++ reference. Browser checks cover full-scene submission, both export scopes, and imported multi-plate selection plus edit protection. Their mocked calibration transport is distinct from native execution evidence. See [the dedicated implementation evidence](CALIBRATION_MULTIPLATE.md).

The pinned VFA, input-shaping frequency/damping and cornering dialogs expose parameter entry and test generation. Their inspected `on_start` handlers do not expose a measured-result save/apply action. This audit therefore does not invent result fields for those modes or treat their absence as evidence of a missing native dialog action. Physical interpretation and printer-dependent automatic calibration remain unverified; no printer is contacted.
