# Native preset resolution and extruder variants

The web server now resolves selected presets through the pinned native configuration helper. This fixes source profiles such as Bambu Lab H2D whose process JSON contains array-shaped scalar options and whose machine/material profiles contain separate Standard and High Flow variants. The original native deserializer, preset normalizer and full-configuration methods determine their values.

Archive settings preserve the complete native vectors. Effective settings expose the values selected by the physical nozzle type/volume and `filament_map`. For example, two H2D PLA slots retain volumetric speeds `[25,40,25,40]` and ownership `[1,1,2,2]`; Standard/High Flow resolves to `[25,40]`. Editing those active values to `[27,43]` retains `[27,40,25,43]` in the archive. Selecting the same named preset twice does not merge independent slot edits.

The project validator accepts bounded, complete variant maps, checks their identities and stride-two machine modes, and rejects incomplete expanded arrays instead of truncating them. Material add/remove reindexes whole variant blocks. Native Prusa material expansion repeats the last material's complete block, while the ordinary Add filament action repeats the first material's block. Existing purge tables remain independent per physical nozzle.

`GET /api/presets/selection` returns normalized default-active scopes. `POST /api/presets/configuration` accepts either `{selection,overrides}` or `{nativeSettings}` and returns both archive and effective settings plus displayed active scopes. The browser resolves project nozzle-volume/material-map changes through that endpoint. The project slicing/export route retains the archive configuration; validation uses effective values. The legacy single-model endpoint uses native-normalized active scopes for its selected configuration.

Source distinctions:

- `PresetBundle.cpp:4836–4978`: system inheritance applies parent values, extends native vector lengths, normalizes instantiated presets and removes misplaced keys. Native user-preset diff inheritance is a different method and is not inferred from this behavior.
- `PresetBundle.cpp:3884–4164`: `full_fff_config(false)` preserves alternatives; `true` selects active variants. GUI background slicing calls `full_config(false)` (`Plater.cpp:7983`); `PrintApply.cpp:1165–1172` applies printer, process and material variants.
- `PrintConfig.cpp:9004`: native variant lookup; `Tab.cpp:7435–7498`: editor indices; `Config.hpp:427`: setting one vector element.
- `Config.cpp:950` joins array input using the native option separator. For the scalar `bridge_speed` (`coFloat`), `ConfigOptionFloat::deserialize` reads the first numeric token. The acceptance case `["57","83"]` becomes `57`. This rule is not generalized to strings, vectors or arbitrary option types.
- `PrintConfig.cpp:2910` sets `filament_printable` to bitmask `3`; `PartPlate.cpp:1924` and CLI `OrcaSlicer.cpp:5951` reject manual use on a physical nozzle not present in that mask.

Evidence uses the installed OrcaSlicer 2.4.2 with isolated datadir/cwd/output. The geometry starts from the independently captured GUI cube fixture, then tests create explicit synthetic H2D/J1 multi-material configurations. These are not captured multi-nozzle GUI projects. H2D Standard/Standard and Standard/High Flow each produce 582 matching motion lines across complete/effective configurations; J1 produces 615. Post-slice native re-export retains inactive values and ownership vectors. H2D ordinary upload and embedded variant browser workflows are exercised separately.

The bundled XL5T manual mapping case preserves its unchanged mask `3` and intentionally receives native exit188 when a model uses material/nozzle3. The native GUI source contains the same rejection. No compatibility mask is broadened or removed. Editing that native mask in a dedicated UI and fresh multi-nozzle GUI acceptance remain separate work. Compatibility-expression evaluation and importing native account/user presets also remain outside this change.

The helper is an explicit build dependency, never compiled on an HTTP request. Health reports `nativeConfiguration` and `capabilities.nativePresetResolution`; a missing or wrong-version helper degrades health and returns503 for configuration/selection endpoints with a build/configuration instruction. There is no approximate JavaScript fallback for catalog resolution. Embedded projects without expanded variants can still be validated/exported by their existing path; expanded embedded contexts require the helper. A helper error retains the user's project and settings.

Focused acceptance: 59 unit/API regression checks (including 8 new queue/vector cases), 4 actual-native cases, and 2 actual-native browser checks. The four native cases passed together in an earlier run. A final combined rerun passed the three positive cases but the XL negative case exited with SIGBUS; its isolated rerun then passed with exit 188 and the expected native diagnostic. Both logs are retained in the implementation handoff; the unexpected native crash is not counted as a successful rejection. The added Prusa acceptance expands a third H2D material while retaining all six variant values and negative-volume part roles.
