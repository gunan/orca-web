# Prime tower placement

The active plate's X/Y values use the native `wipe_tower_x` and `wipe_tower_y` vectors. Editing another plate preserves existing entries; missing entries inherit the first native coordinate, matching the source's indexed fallback. Width, enable and rotation remain native process settings, so they apply to every plate. Cancel discards drafts and Apply is one undo step. Native project export/slicing retains the selected plate's coordinate pair.

The placement editor shows the origin and source-defined settings. The native engine calculates tower depth, ribs, brim and its actual deposited paths; those paths appear in Preview after slicing. Prepare does not claim to show an exact pre-slice footprint, and dragging a tower gizmo is not implemented yet. Out-of-bed origins cannot be applied while enabled; native slicing remains responsible for its full footprint, collisions and machine constraints.

Baseline source: OrcaSlicer 2.4.2 commit `8500fcdccaa10b5099ac20d252af3a7c560046f1`, `PrintConfig.cpp:6812–6894` and `Plater.cpp:11658–11668`, represented in the pinned schemas. [ToolOrdering.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/GCode/ToolOrdering.cpp#L1135) uses the color-vector length to count filaments. Bundled filament presets can omit that project field, so native project generation now supplies the schema default color for every missing slot. Explicit colors remain intact. A malformed filament-to-nozzle vector is rejected before invoking native code.

An initial two-filament prime test crashed the installed engine in filament ordering when colors were absent. After the vector fix, `tests/native/prime-tower.test.js` verifies **45,198** deposited prime-tower segments shift exactly **30 mm in X**, with unchanged model-wall endpoints. Unit tests check plate-index preservation, embedded settings, invalid numbers and explicit/default colors. The browser test checks edits, invalid placement, cancellation and undo. These prove the tested placement path, not full native UI or hardware parity. No printer was contacted.
