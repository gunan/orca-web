# Prusa project import through native Orca source

The installed OrcaSlicer 2.4.2 CLI calls `Model::read_from_file` → `load_bbs_3mf` for every 3MF. The GUI's `Model::read_from_archive` instead dispatches a recognized PrusaSlicer archive to `load_3mf`. The web service now compiles and calls that exact Prusa importer in a bounded, isolated worker. This closes the importer-dispatch gap without converting an assembly to STL.

Pinned source: [Model.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/Model.cpp#L388), [Format/3mf.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/Format/3mf.cpp#L773), [Plater.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Plater.cpp#L6012), [PresetBundle.cpp](https://github.com/OrcaSlicer/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/libslic3r/PresetBundle.cpp#L3022).

## What the native importer actually supports

It retains model geometry, instances and transforms, volume boundaries, names, material assignments, normal/negative/modifier/support roles, and support/seam/color/fuzzy facet annotations. Its model metadata whitelist is exactly: `name`, `volume_type`, `matrix`, `source_file`, `source_object_id`, `source_volume_id`, `source_offset_x`, `source_offset_y`, `source_offset_z`, `extruder`, `modifier`. Source paths are metadata, never paths to read or write. Recovery matrix/source information remains in original configuration provenance; it does not become an extra active transform.

At Format/3mf.cpp 773–804, the native importer intentionally omits Prusa global presets, layer heights/ranges, SLA auxiliary carriers and custom layer events. It also ignores model options outside the whitelist, including arbitrary process overrides. Earlier descriptions implying that the GUI activates all Prusa configuration were incorrect. The service reproduces the source behavior and reports the ignored carriers and filtered model keys. It does not promote ignored data to active Orca settings.

The native GUI uses current printer/process/material configuration. Imports supplied with selected catalog IDs and scoped overrides retain that context. A current embedded configuration can instead be supplied as validated `nativeSettings`; complete material vectors and existing purge cells are retained. Mixed embedded/catalog requests are rejected. Accepted process correction decisions replay through the existing server validator. Missing context uses catalog defaults. If native imported object/part/paint assignments require more slots, the bridge repeats the last selected material and follows the native added-color cycle. Native GUI's cycle index is session-global; the server helper accepts an explicit index and defaults to the first native color for a fresh import. Matching an arbitrary existing GUI session's color counter has not been claimed.

Each instance remains a coherent object group. Parts retain their original local vertex frame and instance/component matrices. This matters even when baked world-space vertices are identical: a 90° instance transform can change native infill direction/order relative to a baked reference. The bridge's differential fixture therefore compares independently specified native local frames, not only world-space surfaces.

## Bounded inactive source preservation

`project.nativeLegacySource` has format `prusa-3mf`, version 1, original Metadata entries as canonical base64, and a report of ignored carriers/filtered model keys. It permits at most 256 whitelisted one-level Metadata entries totaling 16 MiB; unknown fields, traversal, collisions, malformed encodings and invalid report references fail. Export places original bytes under `Metadata/orca-web-legacy-prusa/*.bin` with a validated manifest. Native never sees them under their original active carrier names. Project JSON and exported native 3MF retain these bytes exactly. Import/export performs no filesystem access through their names or contents.

One process-wide queue admits one active and four pending imports across raw jobs and direct project imports. Queue overflow fails explicitly; queued cancellation removes the entry without creating a directory or launching the worker. Queue wait consumes the same deadline passed to every child invocation. The native worker uses a single deadline and cancellation signal, capped logs, bounded input/output, isolated temporary directories and strict pinned-version verification. Native project sanitization validates all resulting typed settings, facet states, filament slots, geometry, bed bounds and source frames. Unsafe post-processing is rejected before native execution, including in ignored Prusa config. See [worker build and licensing](../native/prusa-worker/README.md).

## Verification and limits

- 20 unit cases and one HTTP queue integration case cover exact native metadata filtering, geometry/frame validation, mirrored winding, facet validation, inactive byte roundtrip,16 MiB/entry/path/base64 bounds, unsafe scripts/XML, pinned binary identity and abort/deadline cleanup.
- The synthetic source-format assembly contains three separate volumes: a painted body, a through-hole negative volume and a second-material body, with a 90° instance rotation. Its native import matches 29,750 G0/G1/G2/G3 motion commands against an independently constructed native-frame fixture, over 100 layers with both tools. All four facet channels and original inactive bytes survive web and native 3MF roundtrips.
- Real API jobs at 100% and 98% material compensation produce 100 and 102 layers respectively; both tools and the negative hole remain. Project import preserves a selected 0.16 mm process, adds the required material slot, reports ignored data and exports the original inactive bytes.
- Repeating the imported native input produces identical output. An early reference that baked away instance frames diverged in infill ordering; that diagnostic motivated the explicit frame-preservation regression and was not counted as a passing comparison.

These fixtures are synthetic source-format inputs, not captured Prusa GUI exports. The native browser test opens the Prusa assembly, retains a selected 0.18 mm process, reimports with the current embedded 0.19 mm process, verifies separate roles/slots/painting, and downloads a native 3MF with original inactive bytes. A direct unlocked-GUI import/re-export comparison remains outstanding. Adding material slots to an existing complete multi-physical-nozzle context preserves each native nozzle table and its multiplier; see [physical nozzle purge tables](multi-nozzle-purge.md) for native differential evidence and the separate bundled-preset variant-resolution limits. Unsupported or unclassified third-party carriers are reported or rejected rather than silently treated as supported features. Generic property 3MF continues through the installed native importer/exporter path; see [raw 3MF normalization](raw-3mf-shrinkage.md).
