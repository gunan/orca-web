# Native configuration process lifetime

The configuration cache identifies the current helper before every cache lookup. A bounded file descriptor read hashes the current bytes and records device, inode, length, mtime and ctime; removing or replacing the binary cannot reuse a former result. An identity change during execution rejects the output before it is published or cached.

All applications still share one active/four pending native configuration process slots. Each application owns a separate cancellation lifetime: shutdown aborts and waits for that application's active and queued calls, while unrelated applications remain usable. Request cancellation reasons retain their Error identity, name, status and native diagnostic properties. Queue overflow remains429, deadline expiry504, helper unavailability503; shutdown is an AbortError with503.

Arrangement forwards its cancellation signal through project preparation into native configuration resolution. Its request uses effective selected temperature/nozzle/support vectors while the stored project retains full archive alternatives. Project services expose close() for callers that own them independently; app-owned services share the application's lifetime. Preset configuration HTTP responses preserve operational status codes. This does not change configuration values or claim additional native printer compatibility.

Verification covers replacement with equal-length bytes and restored mtime, missing binary after a cache hit, replacement during execution, custom native errors, explicit caller cancellation, active/queued shutdown and separate application lifetimes. HTTP tests cover application shutdown, preserved status, and geometry cancellation before arrangement process admission.
