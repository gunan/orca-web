# Sliced support preview

The support painting dialog can submit its current draft through the existing isolated native project job pipeline, then display only actual support and support-interface extrusion paths from the resulting G-code. The translucent source mesh is visual context. Layer sliders filter the rendered paths; counts and path lengths come from those parsed movements. No process option is silently enabled or changed. Returning to painting retains the draft; Apply/Cancel retains its normal meaning.

The creation response is allowed to settle on closure so its returned job ID can be cancelled. Polling and G-code reads abort promptly. Only that preview job is cancelled; unrelated jobs are untouched. Validation and engine errors are shown while preserving the draft. G-code reads are limited to 25 MB and parsed paths to 500,000; a truncated result is explicitly marked partial.

This is **not** native pre-slice support-volume mesh parity. The pinned GUI calls [`PrintObject::generate_support_preview`](https://github.com/SoftFever/OrcaSlicer/blob/8500fcdccaa10b5099ac20d252af3a7c560046f1/src/slic3r/GUI/Gizmos/GLGizmoFdmSupports.cpp#L814) and builds support volumes before the normal full slice. The installed CLI does not expose that GUI workflow. Reproducing its exact pre-slice volume meshes, regeneration and native GUI interactions remains an explicit separate acceptance task.

Evidence on OrcaSlicer 2.4.2: four unit/client tests pass for support-only filtering, true path metrics, job ownership, cancellation during pending creation/polling, validation errors and bounded downloads. One real native test passes: manual support paint creates 1,207 support/interface deposition paths across 33 layers, exactly the parsed native support paths; the same geometry without paint creates none. Two browser protocol/rendering cases and two browser-to-native cases pass in the integrated application. Browser-native cases verify that disabled support settings remain disabled and compare the actual rendered segment count with the downloaded native G-code. The enabled/disabled screenshots were visually inspected: the former shows 1,207 support paths around the translucent model; the latter shows no support paths.
